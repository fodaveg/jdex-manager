## JDex Manager 0.6.4

The shared engine can now file a note, a loose file or a whole folder into an ID, like `jd move`, for the Hebra MCP server.

### Engine (`src/jd/public.ts`)
- New: `LibraryMovePort`, `planMoveIntoId`, `applyMovePlan`, `planUndoMove` and `applyUndoMovePlan`.
- The target is the ID's folder or a one-level subfolder of it, made when missing. An ID in the JDex without a folder gets its folder, named as Create ID names it. An optional new name is applied as it moves.
- It refuses, and writes nothing, when the ID is not in the JDex, the target already holds something with that name, the target is inside the folder being moved, or the folder holds something the caller cannot see. No message says what is hidden.
- Before writing, the plan is checked again against the library. A retry after a failure half way completes what is left. Undo puts each piece back where it was, and skips and reports a piece that someone else moved since.

### Hebra and Obsidian
- No behavior changes. Minimum Obsidian app version remains 1.7.2; still requires Hebra plugin API 2.1.

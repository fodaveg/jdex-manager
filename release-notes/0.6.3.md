## JDex Manager 0.6.3

Create ID in Hebra now goes through the shared engine that the Hebra MCP server will use, so an agent and the plugin give the same ID, names and note.

### Hebra
- Create ID plans and writes through `planNewId` and `applyPlan` in `src/jd`, over a `LibraryPort` adapter on the plugin API. Same number, names, template, note body, notices and undo as before.
- Before writing, the plan is checked again against the library: if someone took the number in the meantime, nothing is written and the dialog shows the same "already used" message.
- An invalid subfolder pattern now fails before anything is written, instead of after the note and the folder were created.
- Still requires Hebra plugin API 2.1.

### Engine (`src/jd/public.ts`)
- New: `LibraryPort`, `resolveSettings`, `loadLibraryState`, `planNewId` and `applyPlan`, so hosts without vault paths (the Hebra MCP server) can create a new ID with the plugin's rules.

### Obsidian
- No behavior changes. Minimum app version remains 1.7.2.

## JDex Manager 0.6.7

In Hebra, the plugin reads notes in batches when Hebra offers it, so large JDex operations no longer queue dozens of single reads in front of the rest of the app.

### Hebra
- Built against Hebra plugin API 2.5.0 and declares the optional capability `vault.read.batch`.
- When `api.has('vault.read.batch')` is true, `readNotes` reads up to 200 notes per call with `vault.notesReadBatch`, in the same order, with `null` for notes that no longer exist.
- On a Hebra without batch reads it falls back to single reads, still capped at 4 at a time.
- Still requires Hebra plugin API 2.1.

### Obsidian
- No behavior changes. Minimum app version remains 1.7.2.
